Flex Railway Map 駅周辺データセット設計 v2.0(PoC)

作成日: 2026-09-24 / 対象10駅: 東京・新宿・渋谷・池袋・品川・横浜・川崎・藤沢・大宮・千葉 / 本レポート+同梱データ(schema.json, stations_poc.display.json, stations_poc.meta.json, stations_poc.csv, scripts/)

重要な前提 — 本PoCで「数値が入っている」項目は、すべてこの調査内で実際に取得した観測値のみです。取得できなかった項目は推測で埋めず null とし、理由と取得方法を明記しています。既存項目の crimeIndex / noiseScore / safetyScore / morningCongestion は主観スコアとして廃止または再設計しました。

1. 設計原則 — 値を4+1分類する

分類定義運用ルール
A. observed公的統計・鉄道事業者・自治体等の一次実測値sourceName/Url/Date/retrievedAt が必須
A'. observed (community)OpenStreetMap等の実地調査ベース公開データ「観測」だが網羅性が保証されないため、公式観測とラベルを分離。出典(ODbL)とタグ定義を必ず記録
B. derived定義済みの計算式で算出(例: 円内メッシュ人口の面積加重合計)入力データIDと計算式をschemaに保存。元データ列を必ず併存
C. estimated直接統計がなく推定・参照で得る値推定方法を明示。実測値として表示することを禁止
D. unavailable取得・推定不能null で保存し、理由(reason)を必須記録

既存の単一 status 概念をこの5値に刷新し、「観測値を推定値として扱う」ことを構造的に不可能にしました。

2. 統一定義(全駅共通・駅ごとに変えない)

論点採用する定義
「駅周辺」駅代表点から直線距離 半径800m の円(徒歩約10分・円面積201.06ha)。ポリゴン/徒歩距離は使わない(再現性優先)。都市部の比較用に600m併記オプション
駅代表点本番: 国土数値情報(N02)の駅代表点。PoC: OSMの同一名称駅ノード群の重心
店舗数の検索半径上記800m円内。複数駅の円が重なる場合も駅ごとに独立カウント(重複は仕様)
人口密度の地域単位500mメッシュ国勢調査人口を円内で面積加重合計 ÷ 円内実面積
公園面積円内の公園・緑地ポリゴン(leisure=park/garden または国土数値情報 都市計画公園・緑地)の面積合計
緑地率国土数値情報「土地利用(細分)」メッシュの緑地系分類面積比率(航空写真判定値ではない)
乗降客数「1日平均乗車人員(人/日)」を採用。乗車と降車を混在させない。複数事業者駅は「同一名称駅集合に含まれる全事業者分の合計」(乗換客の二重計上を認め、換算係数は使わない)。事業者間の集計基準差はmetaに注記
朝混雑度駅単位の値は廃止。国交省「都市鉄道の混雑率調査」の主要区間値(最混雑時間帯1時間平均)を区間情報(路線・区間・時間帯・方向)付きで附与。時間帯は区間ごとに公表値(例: 7:30–8:30)
犯罪件数の地域単位警視庁CSVは町丁目単位・座標なし(確認済み)。駅円内件数=町丁目ポリゴンとの交差計算で算出。都道府県により公開形式が異なる点を明記
家賃対象期間=直近3か月成約ベースを推奨。平均か中央値かは中央値(外れ値に強い)を採用。ただし公的統計に駅別値は存在しないため「estimated(参照型)」— 値を恒久保存せず参照先と取得日のみ保存
静かさ/騒音駅別騒音の実測値は全国どの情報源にも存在しない → D. unavailable(proxy案は§5)
安全性スコアは廃止し、元データ(crimeCount800/crimeRateCitywide)を先に置く。safetyScoreはderivedで「全国市区町村犯罪率のp5–p95線形正規化の逆転」(式は§3)
オフィス数OSM office=* は網羅性が低い(下限値)。再現可能な代替として経済センサス事業所メッシュの特定業種従業者数(officeWorkersMesh)を併設

4.4 null項目と理由(取得不能/未実行の全リスト)

項目理由本番での取得方法
dailyPassengersJR東日本の駅別乗車人員ページは列定義(年度・乗車/乗降の別)をHTML上で確定できず、誤記載の恐れがあるため未採用国土数値情報S12(2018年値・非商用ライセンス)を基盤に、各事業者公表値で上書きする二層方式
popNight800 等4項目e-Statメッシュzip取得+面積加重計算を今回は未実行統計GIS 500mメッシュ(2020国勢調査)をGeoPandasで円結合
crimeCount800/crimeRateCitywide/safetyScore警視庁CSVは町丁目単位(座標なし)であり、ポリゴン結合が必要。未実行警視庁犯罪発生情報CSV(年次・8月更新・確認済み)+大都市圏町丁目ポリゴンで800m集計。関東4県は各県警の公開形式に対応
parkAreaM2/greenRatioPctポリゴン面積計算・土地利用メッシュ結合を未実行Overpassで公園ポリゴン取得→球面面積合計/国土数値情報土地利用(細分)
landPriceAvg800国土数値情報地価ポイントの取得を未実行(ダウンロードフォーム経由)国土数値情報 地価(公示+基準地価)ポイントを円内平均
rent1K/rent1LDK公的統計に駅別値が存在しない+民間ポータル相場は恒久保存が規約上困難「estimated(参照型)」— 値は保存せず参照先と取得日のみ記録
noiseScore駅別騒音の実測値は存在しない(環境基準点は地点単位)廃止。proxy(幹線道路からの距離等)はestimatedで別枠提案
routeCount/operatorCount国土数値情報N02の取得を未実行N02一括取得後に自動算出
officeWorkersMesh経済センサス事業所メッシュ結合を未実行e-Stat 500m事業所メッシュ(業種大分類L/M/J等)

実行順序: ①N02+座標マスタ(全駅) → ②Overpass POI(約5,200駅×1クエリ、レート制御で1〜2日) → ③S12乗車人員 → ④メッシュ統計(人口・昼間・事業所・地価) → ⑤犯罪・混雑率(年次差分更新)。推定値を実測扱いにしないため、各値のstatusをパイプラインが自動付与する。

6. JSONデータ構造提案(表示用とメタの分離)

全国展開時は表示用(軽量・キャッシュ可)と出典メタ(重い・年次更新)を別ファイルにします。今回の納品物がそのまま実例です。

stations_poc.display.json  … { "池袋": { "lat":…, "restaurantCount":241, "congestionSections":[131,153], … } }   表示・描画専用
stations_poc.meta.json     … { "池袋": { "restaurantCount": { "value":241, "status":"observed_community",
                                 "sourceName":"OpenStreetMap (Overpass API…)", "sourceUrl":"…",
                                 "sourceDate":"取得日 2026-09-24", "retrievedAt":"2026-09-24" }, … } }   出典・分類・理由
stations_poc.csv           … 全駅×全項目のフラット表(分析用)
schema.json                … 項目定義・分類・情報源・更新頻度のマスタ

各値の必須メタ: value, status(observed/observed_community/derived/estimated/unavailable), sourceName, sourceUrl, sourceDate, retrievedAt, 不可の場合reason。
