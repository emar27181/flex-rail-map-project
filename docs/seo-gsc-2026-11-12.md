# Search Console 実測に基づくSEO改善案（2026-11-12）

## 対象とデータ
- 元データ: Search Console「検索パフォーマンス」エクスポート（2026-11-12取得、実測期間2026-08-11〜11-10、Web検索）。
- 全体: **100クリック / 19,795表示 / CTR 0.51% / 平均掲載順位 13.59**。
- 直近28日: **87クリック / 17,305表示**。前28日は **13クリック / 2,481表示**。露出増にCTRが追いついていない。
- 日本語の `/articles/sapporo-namboku-line-map`: **0クリック / 2,478表示 / 平均7.59位**。今回の最優先検証対象。
- `/en/lines/keikyu-airport-line/`: **9クリック / 631表示**。英語版路線ページは需要があるため縮小しない。
- GSCのクエリ表は1,000件上限・匿名化のため全クエリを網羅しない。ページ単位とサイト全体の集計値は一致しないことがある。

## 今回の差分（P0: 小さく検証）
1. 札幌南北線の記事に、麻生〜真駒内の全駅を**HTMLの駅一覧**として、最初の地図デモの直後に表示する。
2. 駅名・順番は `src/seo/pageModel.ts` が持つ共通路線データから生成する。`ArticleBlock.routeStations` を新設し、記事に駅名をコピーしない。
3. 日・英・中・韓の4言語で同じレイアウト構成とし、見出しを駅一覧に適合させる。
4. 日本語descriptionを検索意図に寄せ、記事の更新日を実際の変更日へ更新する。
5. 16駅が順番どおり描画され、4言語でテーブルが出ることを回帰テストに追加する。

この変更は「掲載順位が上がる」ことを保証しない。検索意図への合致とCTR改善の仮説を試すものである。

## P1: URLの正規化は調査優先（今回、一括変更しない）
GSCには末尾スラッシュあり/なしのURL形式が混在する。ただし、これだけではcanonical不具合・重複インデックスを断定できない。

- Netlifyの本番URLについて両形式の HTTP status / Location / 最終URL / rel=canonical を計測する。
- `/articles/sapporo-namboku-line-map`、`/en/lines/keikyu-airport-line`、主要な `/lines/*` をサンプル確認。
- sitemap、内部リンク、canonical、hreflangが同じ最終URLを指しているか確認する。
- 問題が実証されたパスだけ、既存の `netlify.toml` のクエリ付き記事URLリダイレクトと競合しない形で対応する。
- `src/integrations/seoSitemap.ts`、`src/seo/sitemapCore.ts` はすでに生成・整合性検証を行うため再実装しない。

## P1: 英語版の改善候補（別差分で検証）
- `/en/lines/keikyu-airport-line`: 流入実績がある。既存の `src/seo/lineFacts.ts` の実データに基づくtitle・description生成を維持し、コンテンツ重複やスニペットを先に監査。
- `/en/lines/jr-keiyo-line`、`/en/lines/osaka-midosuji-line` 等も同じ条件で監査。実装に無いslugは勝手に追加しない。
- 自動大量記事生成・根拠のないFAQ/構造化データ・駅名手書きコピーはしない。

## 公開後の評価
公開日以降、同じURLと検索クエリを対象に14日・28日単位でクリック、表示、CTR、掲載順位を比較する。
