# 全国駅ナンバリング調査ログ

更新日: 2026-10-15

## データ管理方針

- 駅番号の正本は `src/data/stationNumbers.ts`。2D・英語表示は既存の `getStationNumber(routeKey, stationName)` を再利用する。
- 公式駅ナンバリングがある路線と、未導入または未調査の路線を区別する。未調査を「番号なし」と断定しない。
- 駅番号は事業者・路線の組合せに紐づく。駅名だけから別路線の番号を流用しない。
- 新しい値は公式路線図・駅案内を確認し、駅名の表記を `routes` に合わせ、出典と確認日を残す。番号の連番推測は禁止。
- データ変更後は `npm run test:data`、`npm run test:types`、`npm run test:unit`、`npm run build` と GitHub CI を確認する。

## 関東全域（1都6県）を先行して調査する

対象: 東京、神奈川、千葉、埼玉、茨城、栃木、群馬。県境をまたぐ路線も対象。駅番号の有無は各事業者・路線の公式資料で確認する。

- **登録済み（既存データ、要原典再監査）**: JR首都圏の主要系統、東京メトロ、都営地下鉄、東急・小田急・京王・京急・西武・東武・京成などの一部、横浜市営地下鉄、TX、モノレール各線など。既存データがあるだけで「公式完全検証済み」とはしない。
- **今回新規確認**: 江ノ電（全15駅）、東急世田谷線（全10駅）、京成押上線（公式確認済み5駅）。
- **押上線のデータ課題**: 公式「京成立石 KS49」が路線データでは「立石」。駅名の修正が利用箇所に及ぼす影響を検証してから別修正で登録する。
- **優先調査候補（番号導入有無も未検証）**: 都電荒川線、JR青梅線・五日市線・相模線・鶴見線など、箱根登山線・伊豆箱根鉄道、秩父鉄道、関東鉄道、富士急行、各地域私鉄・第三セクター線。番号が存在するという意味ではない。
- **重複取り扱い**: 同一駅に事業者・路線ごと複数コードがある場合、路線キーごとに保持する。駅名のみのfallbackは別路線・別地域の番号を返し得るため別PRで是正する。
- **集計の定義**: (1) リポジトリの関東対象路線で駅番号表がある割合、(2) 公式ナンバリングが確認された関東路線の駅単位の登録割合、(3) 未調査路線数を分けて記録。全路線を一律「公式コードあり」として欠落率を数えない。

## 継続調査

- 全国各鉄道事業者の公式資料から「ナンバリング導入済みで未登録」の路線を抽出し、地域ごとに追加。
- `src/data/stationNumbers.ts` の既存登録値も公式出典との突合が必要（本PRで全件確認済みと扱わない）。
- カバー率の母数は「リポジトリに登録されている全路線」と「公式ナンバリングを導入している路線・駅」で異なる。単純な登録率を公式カバー率とは呼ばない。
- `getAnyStationNumber(stationName)` は別路線・別地域の同名駅コードを誤って返すリスクがある。UIの呼び出し元を調査し、路線キーで絞る設計に移行する（既存利用への影響を別PRで検証）。
