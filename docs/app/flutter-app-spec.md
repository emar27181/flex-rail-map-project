# 仕様書: Flex Railway Map アプリ（Flutter, MVP, 2026-11 案）

関連: 企画書 `docs/app/flutter-app-proposal.md` / UI の見直し `docs/app/ui-review-2026-11.md`

この仕様は企画書の「B. ハイブリッド」案に沿う。地図・駅検索・経路・時刻表・設定は Flutter で作り、
記事・ガイド・このサイトについては WebView で今の Web を開く。

## 1. 前提

- 対応 OS: iOS / Android の現行と1つ前の版（始めるときに Flutter の対応表で決める）
- 画面: スマホの縦向きが基本。タブレットは同じ画面を広げる（横に経路の一覧を常に出す）
- 言語: 日本語・英語・中国語（簡体字）・韓国語。初回は端末の言語、設定で変えられる
- テーマ: ライト / ダーク / 端末に合わせる
- 一次情報は今のリポジトリ（`src/data/`・`src/utils/translation.ts`・`src/constants/ui.ts`）。アプリはそこから書き出した JSON を読むだけで、値を手で書き写さない

## 2. 画面構成

地図を常に全画面にし、操作は**上の検索バー**と**下から出るシート**にまとめる。
**深さは最大2段**（今の Web 版は「表示切替」の中が3段・画面 11.6 枚分ある。UI の見直しの B2〜B4）。

| 画面 / シート | 出し方 | 中身 |
|---|---|---|
| 地図（ホーム） | 起動時 | 路線・駅。右上に現在地・北を上に、右に「路線」「レイヤー」 |
| 駅検索（全画面） | 検索バーを押す | 入力欄・最近の駅・現在地から近い駅・候補（漢字/かな/英語） |
| 下部シート: 何も選んでいない | 起動時（小） | よく使う経路・最近の駅 |
| 下部シート: 経路の結果 | 出発と到着が決まったとき（半分） | 候補（所要時間・乗換回数・路線の色）→ 押すと詳細（乗る駅・乗り換える駅・降りる駅と時刻） |
| 下部シート: 駅 | 地図の駅を押す（半分） | 駅名・駅番号・「ここから」「ここまで」・路線ごとの時刻表（路線はタブ） |
| 路線シート | 「路線」ボタン | 検索・経路に関係する路線・表示中・ほか（一覧行 + スイッチ）、全表示/全非表示 |
| レイヤーシート | 「レイヤー」ボタン | 路線図 / 簡略図 / ヒートマップ（MVP の後）を大きなカードで選ぶ |
| 設定（別画面） | 検索バー左のメニュー | 地図の見た目 / 経路 / 駅 / 通知 / 言語 / テーマ / このサイトについて（WebView） |
| 記事・ガイド（WebView） | 設定・駅シートのリンク | 今の Web の該当ページ |

**下部シートの高さ**は3段階（小: 約 96 / 半分 / 全画面）。地図を隠しすぎないよう、経路を出したときは「半分」で止める。

## 3. 機能

### 3.1 MVP

| 機能 | 今の Web 版で対応するもの | アプリでの決まり |
|---|---|---|
| 路線と駅の表示 | `RailwayMap.tsx` | 出発と到着が決まったら、関係する路線だけを出す（既定）。ほかの路線は薄く出すか消すかを設定で選ぶ |
| 駅検索 | `StationSelector.tsx` | 漢字・かな・英語の前方一致。かなの読みが無い駅（今は約9割）は漢字・英語で引く。読みのデータを増やすのは Web と共通の作業 |
| 経路探索 | `src/utils/routeFinder.ts` | Dart に移す（4章）。候補は最大5件。所要時間・乗換回数で並べる |
| 経由駅 | 「経由駅を追加」 | 経路の結果シートの中に置く（検索バーには出さない） |
| 時刻表 | `TimetablePanel.tsx`, `src/data/timetableData.ts` | 経路の進行方向に合う発車だけを出す（CLAUDE.md「時刻表データ実装方針」と同じ）。時刻データが無い路線は「時刻データなし」と書き、別の路線で代用しない |
| 出発/到着の時刻指定 | 出発時刻・出発/到着 | 経路の結果シートの上に1行 |
| 路線の表示切り替え | `RouteSwitchBoard.tsx` | 路線シート。並び順は「経路に関係する → 表示中 → ほか」、ほかは検索で探す |
| 駅番号・ふりがな | 表示設定 | 設定の「駅」 |
| 4言語・ダーク | `translation.ts`, `ThemeContext` | 5章 |
| 記事・ガイド | `/articles`, `/guides` | WebView。アプリ内で開いたことが分かるよう、上に閉じるボタン |
| ディープリンク | `mapDeepLink.ts` の `from` `to` `routes` `lang` | 同じパラメータを受ける（7章） |

### 3.2 MVP の後

| 機能 | 決まり |
|---|---|
| 到着アラート | 降りる駅の N 分前（または N 駅前）にローカル通知。位置情報の「常に許可」は求めず、アラートを使っている間だけ取る。iOS は位置情報の用途説明を書く |
| よく使う経路 | 端末に保存（最大10件）。ホーム画面ウィジェットに1件 |
| オフライン地図 | 背景タイルを地域ごとに端末へ（提供元の利用条件で許される範囲だけ。4.3） |
| ヒートマップ | `station-stats-data.json` の実データだけ。データの無い駅は灰色（CLAUDE.md の絶対ルールと同じ。推定値は既定で出さない） |
| 簡略図 | `SchematicMap.tsx` / `DiagramMap.tsx` の配置データを書き出して描く |

### 3.3 作らない（当面）

- 立体表示（`Terrain3DView.tsx`）・列車の位置のデモ: Flutter での作り直しが重い
- 全画面 / 通常表示の切り替え: アプリは常に地図が全画面

## 4. データ・経路探索・地図

### 4.1 データの書き出し（2026-11 作成済み）

`npm run app:data`（`scripts/app-data/export.mts`、中身は `scripts/app-data/buildAppData.ts`）で次を JSON にする。
既定の書き出し先は `app/assets/data/`（git に入れない。手で直さない）。中身の検査は `tests/unit/scripts/appData.test.ts`。

| ファイル | 元 | 中身 | 大きさ（2026-11） |
|---|---|---|---|
| `routes.json` | `src/data/routes.ts`（`routes` `routeColors` `routeNames`）・`routeUrlCodes.ts` | 路線 491 本（キー・URL の路線コード・名前・色・駅の並び・駅間の所要時間・急行停車） | 約 600KB |
| `stations.json` | 同上 + `stationUrlParams.ts`・駅名の訳の表 | 駅 6,001（名前・緯度経度・URL の slug・通る路線）。駅は名前で1つにまとめる（経路探索と同じ） | 約 960KB |
| `translations.json` | `translation.ts`（`uiTranslations` `uiChinese` `uiKorean`） | 画面の文言 360 個の4言語。Flutter の ARB に変換して使う | 約 50KB |
| `timetables.json` | `timetableData.ts`（`timetableLines` `TIMETABLE_SOURCE`） | 路線ごと・方向ごとの発車時刻と出典 | 約 230KB |
| `transfers.json` | `walkingTransfers.ts`・`throughServices.ts` | 徒歩の乗り換え・直通運転（経路探索に使う） | 約 16KB |
| `tokens.json` | `src/constants/ui.ts`（`FS` `SEMANTIC` `NEUTRAL` `TARGET`）・`L`・`getThemeColors` | 5章のデザインの値。押せる大きさはアプリ用に `target.app = 48` | 約 2KB |
| `route-golden.json` | `routeFinder.ts` の答え | 経路の正解データ（4.2） | 約 100KB |
| `manifest.json` | — | 形の版（`schemaVersion`）・中身から決めた版（`version`）・各ファイルのハッシュと大きさ | — |

- 訳が無いものは **null**。Web の表示用の関数（`translateStation` など）は訳が無いと英語や日本語で埋めるので使わず、訳の表を直接引く。
  2026-11 時点: 駅名の英語 6,001 / 中国語 6,000 / 韓国語 1,065、路線名の中国語・韓国語の表は無い（Web は英語で出している）。どの言語で埋めるかはアプリが決める
- `version` は中身から決める（中身が同じなら同じ版）。アプリは版が変わったときだけ取り直す
- データファイルの規約（`docs/data-editing-guide.md`）は今のまま。アプリのためにデータファイルを書き換えない
- **更新**: 同じ JSON を Web（`/app-data/<版>/`）にも置く。アプリは起動時に `manifest.json` を見て、新しければ取り直す（審査なしでデータを直せる）。取れなければ同梱の版で動く（Web に置く仕組みは未作成）
- 時刻表の駅間時間の扱い・ヒートマップ（`stats.json`）は、使う段階で足す

### 4.2 経路探索

- `routeFinder.ts`（約680行）と、それが使う `legTime.ts`・`routeAdjacency.ts`・`throughRouting.ts` を Dart に移す。アルゴリズムは変えない
- **答えがずれないための検査**: 書き出しと同時に `route-golden.json` を作る（主な駅 20 の組 + 関東の駅から一定の間隔で選んだ組、計 144 組の上位5件。乱数は使わない）。
  Dart のテストは同じ版の `routes.json` などを読んで経路を引き、`route-golden.json` と同じ答え（区間の路線・始点・終点・所要時間・乗換回数）になるかを確かめる。
  正解はデータと同じ版から作るので、路線データを直しても食い違わない。Web 側で探索のしかたを直したときは、Dart 側も同じように直す
- **徒歩の乗り換えは区間にならない**: routeFinder は徒歩の乗り換え（東京↔大手町、秋葉原↔岩本町など）を区間として持たず、次の区間がその駅から始まる。
  東京→新宿の候補が「丸ノ内線 大手町→新宿」から始まることもある。Dart 版もこの形を再現し、画面で「徒歩 N 分」を補って見せる
- 経路が見つからない組（25 組。ロープウェイなど他とつながらない路線）も正解に含める。Dart 版も「見つからない」を返すこと
- 時間のモデルの既知の問題（駅数の多い私鉄が各駅停車基準で遅く出る。CLAUDE.md の小田急線の件）は Web と共通の課題として扱う

### 4.3 地図

- 描画: `flutter_map`（Leaflet と考え方が近い）。路線は折れ線、駅は円 + 名前の札
- **背景タイル**: 今の Web 版が使う OpenStreetMap の標準タイル（`tile.openstreetmap.org`）はアプリでは使わない。
  OSMF の利用方針は、アプリを識別できる User-Agent を求め、大量取得や端末への保存（オフライン用の一括取得）を認めていないため。
  提供元（MapTiler・Stadia Maps など）か、自前の PMTiles（Protomaps）から選ぶ（企画書の「決めてほしいこと」4）
- 背景を消したときの簡易な日本の輪郭（`japanOutline.ts`）も書き出して使う（タイルが取れなくても路線図は描ける）
- 駅名の札が重ならないよう間引く。経路を出したときは「乗る駅・乗り換える駅・降りる駅」だけ時刻つき、途中は点だけ（UI の見直しの C1）
- 重なり順は Web の `src/constants/mapLayers.ts` と同じ考え方（路線数の多い駅ほど上、出発・到着は最上）

## 5. デザイン

- 色・文字の大きさ・余白・角の丸みは `tokens.json` から `ThemeData` を作る。Dart 側に値を直接書かない（Web の「定義元から取る」規則と同じ）
- **押せる大きさは 48 以上**（Android 48dp / iOS 44pt の大きい方にそろえる）。見た目が小さい部品も、押せる範囲は 48
- 文字は 12 以上。OS の文字の大きさ設定に合わせて大きくなる（地図の駅名も最低 11 は保つ）
- コントラストは 4.5:1 以上。`tokens.json` を書き出すときに、文字色と背景色の組を検査する（今の Web 版で 2.8:1 の組がある。UI の見直しの C3）
- 状態は塗りで示す（選んだときに枠の太さ・文字の太さを変えない）
- 絵文字は使わない。アイコンは Web の lucide に近い線のアイコン（`lucide_icons` など）でそろえる
- 影は使わない（Web と同じ方針）

## 6. 位置情報・通知・権限

| 権限 | いつ求めるか | 断られたとき |
|---|---|---|
| 位置情報（使用中のみ） | 「現在地から」を押したとき | 駅検索で選んでもらう。案内は1回だけ |
| 位置情報（バックグラウンド） | 到着アラートを初めて入れたとき（MVP の後） | アラートは画面を開いている間だけ動く |
| 通知 | 到着アラートを初めて入れたとき | 画面の中の表示だけにする |
| 追跡（iOS の ATT） | 広告の同意画面（UMP）の後 | 個人に合わせない広告にする |

起動直後にまとめて許可を求めない。

## 7. ディープリンク

- `https://flex-railway-map.netlify.app/?from=<駅slug>&to=<駅slug>&routes=<路線コード>&lang=<言語>` をアプリで開けるようにする（iOS の Universal Links / Android の App Links）
- 駅は `stationUrlParams.ts` の英語 slug、路線は今の短いコード（`yama` `chuo` など）をそのまま使う。書き出しの `stations.json` に slug を入れる
- アプリが入っていなければ今までどおり Web が開く

## 8. 広告・計測・同意

- 広告: AdMob。**決めた位置にだけ出す**（Web の方針と同じ）。置くのは「経路の結果シートの一番下」と「設定画面の一番下」の2か所の横長バナーだけ。全画面広告・起動時の広告・地図に重なる広告は使わない
- 同意: Google の UMP（欧州など同意が要る地域）→ iOS の ATT の順。自作の確認画面を挟まない
- 計測: Firebase の Analytics（GA4 と同じ仕組み）。送るのは画面の表示・経路を出した・駅を押した・言語など。**駅名の組み合わせや位置は送らない**（Web の GA4 と同じ方針）
- プライバシーポリシーにアプリの節を足す（位置情報・通知・広告・計測）

## 9. 品質・テスト・CI

| 検査 | 中身 |
|---|---|
| `flutter analyze` / `flutter test` | Dart の型・ユニットテスト |
| 経路の正解データ | 4.2。Web と同じ答えを出すか（Dart 側）。書き出しの中身は Web 側の `tests/unit/scripts/appData.test.ts` |
| 押せる大きさ | 全画面のウィジェットテストで、押せるものが 48 未満なら落とす |
| コントラスト | `tokens.json` の組を検査 |
| 4言語の文字の収まり | Web の `textFit.render.ts` と同じ考え方で、ボタンの文字が切れていないか |
| 画面の写真 | 主な画面のゴールデンテスト（見た目が変わったら分かる） |

- CI: GitHub Actions に `app` ジョブを足す（Linux で analyze・test・Android ビルド。iOS ビルドは macOS の実行環境で、リリースのときだけ）
- 起動から地図が出るまで 2 秒以内（中くらいの Android 端末で測る）。同梱データの読み込みは別スレッドで

## 10. リポジトリの置き方

```
flex-rail-map-project/
├── src/ …… 今の Web（一次情報）
├── scripts/app-data/ …… JSON と経路の正解データの書き出し（npm run app:data）
└── app/ …… Flutter のアプリ（新規）
    ├── lib/
    ├── assets/data/ …… 書き出した JSON と正解データ（npm run app:data で作る。git に入れない）
    └── test/
```

- 同じリポジトリに置く（データの変更とアプリの対応を1つの PR で見られる）
- `app/` の変更だけで Web の本番ビルドが動かないよう、`scripts/netlify-ignore.mjs` の `NON_DEPLOY_PATHS` に `app/` を足す
