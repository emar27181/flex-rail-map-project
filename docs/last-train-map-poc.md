# 終電マップ PoC — 既存地図UIへの統合

## 通常の画面への取り込み（2026-11-13）

試作URL（`?experiment=last-train`）を付けなくても、通常の駅選択パネルのボタン列に **「終電モード（試作）」** を出す。
- ボタンを押したときだけ終電の画面になる（基準時刻の表示・到達できる駅と区間の絞り込み）。OFFで通常の表示に戻る
- ボタン名に「試作」と入れ、`title` と駅ラベルの `*` で架空ダイヤであることを示す。**実際の終電検索には使えない**ことは変わらない
- 試作URLのときだけ地図を実地図表示で開く（従来どおり）。通常の画面ではボタンを押したときに実地図へ切り替える
- 実装は `StationSelector` の `lastTrainButton`（ボタンを出す）と `RailwayMap` の `lastTrainUiActive`（試作URL か ON の間だけ画面を切り替える）

## 確認方法

PR #106 の Deploy Preview ホームを **/?experiment=last-train** 付きで開く。
- 例: https://deploy-preview-106--flex-railway-map.netlify.app/?experiment=last-train
- 以前の /labs/last-train はこのURLへリダイレクト（独立した地図をレンダリングしない）
- 通常の / や本番 main/develop は変更しない
- 目視確認が終わるまで試作PRはマージしない

## 実装原則

専用の別マップ・SVG・CSSデザインは作らない。

- **地図**: 既存の RailwayMap 内の MapContainer（Leaflet）
- **駅検索**: 既存の StationSelector の出発駅・到着駅と時刻設定をそのまま維持する
- **路線**: 既存地図の Polyline / offsetPositions / routeColors を再利用して区間ごとの透過を変更
- **駅マーカー**: 既存の renderStationMarker / createStationIcon を再利用
- **操作部品**: 既存の `StationSelector` の駅・時刻欄、`ui/atoms/Button` のトグルだけを使用（専用スライダーも別パネルも作らない）
- **時刻操作**: `timetableBaseTime` という元の出発時刻欄を共用。PC・スマホ・全画面に追加の時刻入力欄は作らない
- **言語**: 共通駅名翻訳と4言語の表示辞書を利用

## 今回の試作内容

1. URL に experiment=last-train を指定すると、既存の地図・出発駅・到着駅入力・所要時間等のボタンをそのまま表示する（終電フィルタ初期OFF）
2. 通常の時刻入力欄は初期表示時の**現在時刻**（通常モードと同じ state）。到着駅未設定でも編集できる
3. 既存の「所要時間を表示」と同じボタン列にある**終電モード**をONにしたときだけフィルタを適用。到着駅の指定がなければ画面に選択案内を出す
4. フィルタON時は既存Leaflet路線図上で、試作の到達可能駅と路線区間を表示。未到達・期限切れ区間は薄くする
5. 元からある時刻入力（初期値は現在時刻）を変更すると到達可能駅・区間は減少していく。専用スライダー・自動再生は廃止。0時以降は内部で24:xxとして扱う
6. モードON時は「表示路線の切替」にある既存の候補路線数設定（1・2・3・5・10、**初期値5**）を使う。到着駅に直接乗り入れる路線と、確認済みの直通系統は全件表示し、上限より少なければ乗換先の路線を順番に追加して最大5路線にする。直接乗り入れる路線だけで設定値を超える場合はそれらを優先し上限を超えて表示する。採用した路線内の駅は省略せず、地図を自動調整する
7. ボタンは常に押せる。到着駅未選択なら、路線切替と同じ共通Snackbarで「終電モードを使用するには、到着駅を設定してください。」と通知し、元の到着駅入力にフォーカスする。設定済みなら既存の路線数上限内で架空の試験ダイヤを生成する
8. 試作モードをOFFにすると、通常の駅選択・路線図表示に戻る。通常の `/` は変更しない
9. PC・スマホ・全画面の3経路で同じ StationSelector 内の共通操作を表示する

## 重要な注意

**実際の終電検索には使用不可。架空のダイヤによる表示だけのPoC。**

- 従来は山手線・中央線・京浜東北線の一部のみだったが、現在は到着駅から直接乗り入れる路線（確認済みの直通系統を含む）を優先し、その後は乗換回数の少ない順に既存の候補数設定（初期値5）まで追加する（元の駅位置データを使用）
- デモ便の発車間隔と運行終了時刻は架空の値
- 乗換4分も架空の試験条件で、駅構造や実ダイヤを反映しない
- 小田急江ノ島線⇔小田原線は `THROUGH_SERVICES` の既存直通定義を参照し、相模大野を跨ぐ**同じ架空列車ID**を生成する。直通デモ便は乗換不要、相模大野止まりの別便は直通扱いしない
- **直通列車があることと、すべての列車が直通することは異なる。** 何時発の便が直通するかは実時刻表未連携のため判定できない
- その他の直通は、共有接続駅が明確な2路線だけを試験的に連結。3路線以上の連続直通や離れた駅の接続は勝手に推論しない
- 24:xxは同一営業日の深夜時刻として扱う
- 乗り入れ、列車ID、曜日、臨時運休、改札、終点の実際の情報を使用しない
- 「末端から規則的に消える」とは限らない。乗換や複数路線の接続によって枝分かれする


## 今後のUI実装ルール

**既存UIを拡張するときは二重のパネル・入力欄・スライダー・別地図を作らない。**
本試作の教訓と再発防止策は `docs/ui-mode-extension-guide.md` にまとめた。
`CLAUDE.md`・`AGENTS.md`・`docs/design-system.md` の規則一覧・デザイントークンスキルから案内し、`tests/unit/components/ui/noDuplicateModeUI.test.ts` で検証する。

## 検証と正式化の条件

- 単体テスト: 日付またぎ、乗換猶予、時刻とともに減る到達可能な駅数
- デザイン/型/ビルドとブラウザ描画CI
- プレビューで「元のマップのまま操作できること」をPCとiPhoneで目視確認
- GTFS等の商用利用条件を満たした時刻表・運転日・便ID・乗換データの確保
- 実データが無い駅は「データなし」とする。架空の時刻を実運行として出さない
