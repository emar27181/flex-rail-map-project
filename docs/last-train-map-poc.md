# 終電マップ PoC — 既存地図UIへの統合

## 確認方法

PR #106 の Deploy Preview ホームを **/?experiment=last-train** 付きで開く。
- 例: https://deploy-preview-106--flex-railway-map.netlify.app/?experiment=last-train
- 以前の /labs/last-train はこのURLへリダイレクト（独立した地図をレンダリングしない）
- 通常の / や本番 main/develop は変更しない
- 目視確認が終わるまで試作PRはマージしない

## 実装原則

専用の別マップ・SVG・CSSデザインは作らない。

- **地図**: 既存の RailwayMap 内の MapContainer（Leaflet）
- **駅検索**: 既存の StationSelector の到着駅欄だけを表示する
- **路線**: 既存地図の Polyline / offsetPositions / routeColors を再利用して区間ごとの透過を変更
- **駅マーカー**: 既存の renderStationMarker / createStationIcon を再利用
- **操作部品**: 既存の Button / Slider / Select、FS、L、getThemeColors を利用
- **時刻操作**: StationSelector 内に LastTrainModeControls を差し込む。PC・スマホ・全画面で同じ内容
- **言語**: 共通駅名翻訳と4言語の表示辞書を利用

## 今回の試作内容

1. URL に experiment=last-train を指定すると、既存の地図・出発駅・到着駅入力・所要時間等のボタンをそのまま表示する（終電フィルタ初期OFF）
2. 通常の時刻入力欄は初期表示時の**現在時刻**（通常モードと同じ state）。到着駅未設定でも編集できる
3. 到着駅（試作対象駅）を選んで、既存の「所要時間を表示」と同じボタン列にある**終電モード**をONにしたときだけフィルタを適用
4. フィルタON時は既存Leaflet路線図上で、試作の到達可能駅と路線区間を表示。未到達・期限切れ区間は薄くする
5. 時刻スライダー（現在時刻と双方向に同期）と自動再生を使い、時間を進めると到達可能駅・区間は減少していく。0時以降は内部で24:xxとして扱う
6. モードON時は試験対象の**全駅**が画面に収まるよう地図を自動調整し、表示上限による到達可能駅の取りこぼしはしない（ただし試験データ自体は3路線の一部に限定）
7. 到着駅が試作範囲外なら有効化ボタンを非活性にして、対応する試験データが無いことを表示
8. 試作モードをOFFにすると、通常の駅選択・路線図表示に戻る。通常の `/` は変更しない
9. PC・スマホ・全画面の3経路で同じ StationSelector 内の共通操作を表示する

## 重要な注意

**実際の終電検索には使用不可。架空のダイヤによる表示だけのPoC。**

- 山手線・中央線・京浜東北線の一部のみ（元の駅位置データを使用）
- デモ便の発車間隔と運行終了時刻は架空の値
- 乗換4分も架空の試験条件で、駅構造や実ダイヤを反映しない
- 24:xxは同一営業日の深夜時刻として扱う
- 乗り入れ、列車ID、曜日、臨時運休、改札、終点の実際の情報を使用しない
- 「末端から規則的に消える」とは限らない。乗換や複数路線の接続によって枝分かれする

## 検証と正式化の条件

- 単体テスト: 日付またぎ、乗換猶予、時刻とともに減る到達可能な駅数
- デザイン/型/ビルドとブラウザ描画CI
- プレビューで「元のマップのまま操作できること」をPCとiPhoneで目視確認
- GTFS等の商用利用条件を満たした時刻表・運転日・便ID・乗換データの確保
- 実データが無い駅は「データなし」とする。架空の時刻を実運行として出さない
