ユーザーの指示（2026-09-29）をそのまま整理したもの。

- 対象リポジトリ: https://github.com/emar27181/flex-rail-map-project
- 本番サイト: https://flex-railway-map.netlify.app/

## 1. 集客

**自律的に進めてよい**: 調査・施策選定・記事構成・動画台本・計測計画。記事の執筆とプレビューまで
（記事の書き方は `docs/article-writing.md`）。

**まだ行わない**: 公開（本番反映）、SNS 投稿、営業連絡、有料広告の出稿。

進捗台帳: `docs/growth-progress-ledger.md`

## 2. 路線データ整備

調査だけで終わらず、**収集・検証・実装・PR 作成まで**進める。

### 収集対象

- 駅の緯度経度、読み、駅番号、所属路線
- 実際の線路に沿った座標列、カーブ、分岐、接続
- 本線・支線・直通系統・共用区間の関係
- 取得できる範囲で標高、高架・地上・地下の区分

守ること:

- **地形の標高と線路自体の標高は別に管理する**
- **上下関係だけ分かる情報（OSM の `layer` など）を、メートル単位の高さへ変換しない**
- **不明値は欠損として扱い、推測で埋めない**（CLAUDE.md「データに関する絶対ルール」）

### 作業手順

1. 最新 `main`、`CLAUDE.md`、既存 PR、データ構造、収集処理を確認する
2. 利用条件と精度を確認できるデータソースを比較する
3. まず1路線で、収集から地図表示まで一通り完成させる
4. 出典・取得日・利用条件・座標系・高さの基準を記録する
5. 駅との対応、線路の連続性、分岐、異常な座標を検証する
6. 再実行可能な収集・更新処理を用意する
7. 型チェック・ユニットテスト・ビルドを通して PR を作る

最初の候補は東海道線・湘南新宿ライン・小田急線。データの入手性と対応付けの確実さから1路線を選ぶ。
**全路線を一括変更せず、検証できた範囲を順次 PR にする。**

### PR に含めるもの

- 変更理由と対象範囲
- データ出典・利用条件
- 変更前後の地図
- 検証結果、欠損、判断保留の箇所
- 収集処理の再実行方法
- Netlify ボットで確認したプレビュー URL・コミット・状態

進捗台帳: `docs/data-maintenance-ledger.md`

## PR とマージ

- **集客とデータ整備は別の PR にする**
- `main` への直接変更・自動マージは行わない
- 本番反映はユーザーの目視確認後

## 自律運用

- 細かな実装判断で毎回止まらず、既存設計に合わせて進める
- 未確認事項があっても、独立して進められる作業は続ける
- 既存作業を重複させず、成果物と進捗台帳を保存する
- 取得件数だけでなく、**検証済み・反映済みの件数**を報告する
- GitHub への書き込み権限が無い場合は、パッチと PR 本文まで完成させ、必要な接続設定をまとめて知らせる。
  **作成していない PR を作成済みと報告しない**
