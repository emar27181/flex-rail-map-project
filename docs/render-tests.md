# 描画テスト（`npm run test:render`）

ビルドしたサイト（`astro preview`）を実際のブラウザ（Chromium）で開き、**画面に描けているか**を確かめるテスト。
CI（`.github/workflows/ci.yml` の `render` ジョブ）が PR ごとに動かす。設定は `playwright.render.config.ts`、テストは `tests/render/`。

ユニットテスト（vitest / jsdom）では WebGL も Leaflet の描画も動かないため、
「型もテストも通るのに、画面が真っ黒・動かすと固まる・駅名が重なる」といった不具合はここでしか見つからない。

## 何を確かめているか（2026-10-14）

| ファイル | 確かめること | 端末 |
|---|---|---|
| `map2d.render.ts` | 地図・路線（SVG の線）・駅（マーカー）が描かれ、一色の画面でない。実行時エラーが無い | PC・スマホ |
| `terrain3d.render.ts` | 立体表示の描画面（WebGL）に地面・線・駅が描かれている（色の種類・背景以外の割合）。実行時エラーが無い | PC・スマホ |
| 〃 | 駅名が重ならず、上限（40）以下 | PC・スマホ |
| 〃 | 設定はアイコンから開き、最初は閉じている。アイコンは浮かぶボタンの大きさ（`FLOATING_ICON_BUTTON_SIZE.md`） | PC・スマホ |
| 〃 | 回している間の6コマが、どれも描けていて、前のコマから変わっている（真っ黒・固まったコマが無い） | PC |
| 〃 | スマホ全画面で、設定のアイコンが「表示切替」の右に同じ高さで並ぶ | スマホ |

**テストが本当に壊れを見つけるか（わざと壊して確かめた, 2026-10-14）**

| わざと入れた壊れ | 落ちたテスト |
|---|---|
| 毎フレームの描画をやめる（最初の1コマで固まる） | 回している間のコマが変わらない |
| 描画を全部やめる（真っ黒） | 描画面の色の種類が少ない |
| 駅名の重なり判定をやめる | 駅名が重なる |

最初の版は、描画面の撮影に駅名やボタン（DOM）が写り込み、描画を止めても通ってしまった。
描画面を撮るときは `screenshotCanvasOnly`（`tests/render/helpers.ts`）で、上に重なる DOM を隠して撮る。

## 足すときの決まり

- **描画に関わる変更**（地図・立体表示・地図の上に浮かぶ UI）を入れたら、この表のどれかで確かめられているかを見る。
  足りなければ、その変更が壊れたら落ちる検査を足す
- 検査を足したら、**一度わざと壊して落ちることを確かめる**（上の表に1行足す）。通るだけのテストは役に立たない
- 画面の撮影は `tests/render/png.ts` の `pngStats`（色の種類・いちばん多い色以外の割合）で数える。画像の見た目そのもの（ピクセル単位の一致）は
  フォント・GPU で変わるので比べない
- 外部への通信（地図タイル・解析）は CI で失敗しても描画の不具合ではないので、実行時エラーから除く（`collectErrors`）

## 手元で動かす

```bash
npm run build
npm run test:render                     # Playwright のブラウザが入っているとき
PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npm run test:render   # サンドボックス（ブラウザが別の場所）
```
