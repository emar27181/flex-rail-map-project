# 既存UIへのモード・機能追加マニュアル

**規則の一次情報:** `docs/design-system.md` の「規則一覧（CI で検査）」。
新機能が増えても、同じ目的の入力・ボタン・パネル・地図を複製しない。
終電マップ試作 PR #106 で専用SVG・専用パネル・専用時刻スライダーを作り、元のUIと重複したことから制定。

## 原則と優先順位

1. **新しい機能は既存画面のモードとして実装する。** 別の画面・パネル・フォームを先に作らない。
2. **既存の値を一元利用する。** 駅 = `StationSelector` の `arrival` / `departure`、時刻 = `RailwayMap` の `timetableBaseTime`。同じ意味の入力stateを別に持たない。
3. **追加操作は、必要最小限の既存ボタン列のON/OFF。** 既存 `ui/atoms/Button` に `pressed` を渡す。独立したフィルタボタン群・操作欄を足さない。
4. **機能ON時に元の描画結果だけ変える。** 既存のLeaflet `MapContainer`、`Polyline`、`renderStationMarker`、路線色と共通レイアウトを使う。
5. **OFFで元の表示に完全復帰。** 駅・時刻入力は保持。試作は `?experiment=last-train` などで公開導線から分離し、承認前に `develop` / `main` へマージしない。
6. **PC・スマホ・全画面を同じコンポーネントで扱う。** `StationSelector` に並列UIを作らない。
7. **不足している入力は共通Snackbarと既存入力欄で促す。** `ui/molecules/Snackbar` を路線切替と同じ位置に表示し、入力欄にフォーカスする。専用ダイアログや新しいパネルは作らない。
8. **計算・データとUIを分離する。** 終電の逆探索や路線の抽出は `src/utils/lastTrainDemo.ts`。表示に関する制御だけ `RailwayMap.tsx` に置く。
9. **見せてはいけない不確かな結果は区別する。** 終電PoCは架空ダイヤ。既存ボタンの `title` と地図上の時刻ラベル末尾 `*` で試験データであることを示す。正式ダイヤとして案内しない。
10. **例外:** 新規操作が既存UIで表現できず、タスク上の必須要件が明確な場合だけ別UIを検討し、既存部品への統合不可の理由と画面差分をPRに書く。

## 終電モードの利用手順

- PRプレビュー: `https://deploy-preview-106--flex-railway-map.netlify.app/?experiment=last-train`
- 通常の駅選択パネルで **到着駅** と **基準時刻** を入力（時刻の初期値は現在時刻）。
- 「所要時間を表示」などと同列の **終電モード** をONにする。
- 元の地図上で、到着駅へ向かえる駅・路線区間を試験データで絞る。駅ラベルの時刻は架空の最遅出発時刻。
- **時刻を変更する場合は、元からある時刻欄だけを使用する。** 専用スライダー・自動再生・駅選択フォーム・集計パネルは追加しない。
- ボタンをOFFにすると通常の表示に戻る。到着駅や時刻の入力内容を勝手に初期化しない。
- 到着駅を未選択で押すと、路線表示切替と同じ共通Snackbarで「終電モードを使用するには、到着駅を設定してください。」を表示し、既存の到着駅欄にフォーカスする。
- 既存の「表示路線の切替」にある候補路線数設定（1・2・3・5・10、**初期値5**）を終電モードでも共用する。直接乗り入れる路線・確認済み直通路線を全件優先し、残り枠を乗換1回・2回…の路線で満たす。直接つながる路線が5本を超える場合は直接路線を削らない。別設定を作らず、**採用した路線内の駅は一切間引かない**。架空の時刻であることを正式版の結果と混同しない。

## 集合駅を探すモード（2026-11-12）

複数の出発駅から、お互いに行きやすい駅を探す。**新しい入力欄・パネル・地図は作っていない。**

- ボタン: 所要時間ボタンと同じ列に「集合駅を探す」を1つ足しただけ（`StationSelector` の `Button` の `pressed`）
- 出発駅の一覧: 出発駅欄 + 既存の「追加出発駅」`extraDepartures`（凡例の「複数出発駅」と同じ状態）。駅選択パネルの「経由駅を追加」欄は、このモードの間だけ「出発駅を追加」として同じ状態を編集する（経由駅の状態には触れない）
- 出発駅の行は人数に合わせて増減できる: 「出発駅を追加」を押すたびに、出発駅欄と同じ見た目（緑の塗り・✕・同じ横幅）の行が「出発駅 2」「出発駅 3」…と縦に増え、✕で減らせる。経由駅のときのチップ表示にはならない
- 結果: 出発駅が2つ以上そろったら、駅選択パネルの中に候補5件（いちばん遅い人の所要時間が短い順）。押すと既存の到着駅に入る
- 地図: 駅ラベルは既存の所要時間ラベルの位置に「全員が着くまでの最大時間」を出す（元のLeaflet・駅マーカーのまま）
- 計算: `src/utils/meetingPoint.ts`（出発駅ごとに `findStationsWithinTime` = ダイクストラで全駅への所要時間を出し、駅ごとに比べる）。UIからは分離
- 検査: `tests/unit/utils/meetingPoint.test.ts`、`tests/render/meetingPoint.render.ts`
- 所要時間は路線データによる目安で、実際のダイヤではない（画面の注記にも書いてある）

## 実装のチェックリスト

- [ ] 同じ値の二重入力・二重state・二重保存先がない
- [ ] 変更箇所が既存 `StationSelector` / `RailwayMap` に統合されている
- [ ] 新規の専用パネル・モーダル・スライダー・別地図が追加されていない
- [ ] ボタンOFF時の見た目・経路選択・操作が従来どおり
- [ ] ON時に到着駅と既存時刻入力の変更が地図へ反映される
- [ ] PC/スマホ/全画面で同じデータ・同じトグル
- [ ] 試験データは架空と区別し、正式運行の説明として掲載しない
- [ ] 単体・UI構造テストに加え、Playwrightでボタン前後の入力数と地図表示を検証
- [ ] `npm run test:types`、`npm run test:design`、`npm run test:unit`、`npm run build` が成功
- [ ] PRのプレビューを人が確認するまで本番にマージしない

## 再発防止テスト

- `tests/unit/components/lastTrainMapIntegration.test.ts`: 専用パネルを作り直さない・既存駅/時刻を使う
- `tests/unit/components/ui/noDuplicateModeUI.test.ts`: 同じ目的の追加UIと試作固有スライダー禁止
- `tests/render/lastTrainMap.render.ts`: 切り替え前後で入力欄の個数が増えない、時刻変更と到着駅へのフォーカスを検証
- `tests/unit/utils/lastTrainDemo.test.ts`: 計算をUIから分離し、時刻後退で到達可能駅が増えない

## 機能追加時のPRレビュー項目

`UI差分：追加した操作は何か／既存のどの操作を再利用したか／OFFの時に何が変わるか` をPR説明に書く。
終電試作のように既存と似た目的のUIが増えている場合は、**新しい画面を仕上げるより統合・削除を優先**する。

## プレビュー運用

Netlify は自動プレビューのビルド時間を節約するため明示的な `[netlify-preview]` コミットだけを実行する。
試作UIを変更した最後のコミットにこのタグを付け、プレビューで**入力欄の数・押した状態・時刻と路線図の連動・OFFでの復帰**を確認する。
`develop` や `main` へは、実機目視の了承が得られるまでマージしない。
